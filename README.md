# دليل الكفاءات الصحية لعائلة النتشة — المشروع التقني

تطبيق ويب عربي (RTL) مبني بـ **Next.js + Tailwind CSS + Supabase**، وفق وثيقة المتطلبات
[`دليل_الكفاءات_الصحية_لعائلة_النتشة_المواصفات_الشاملة.md`](./دليل_الكفاءات_الصحية_لعائلة_النتشة_المواصفات_الشاملة.md).

## هيكل المشروع

```
app/
  layout.tsx              التخطيط العام (RTL، الخطوط، العنوان)
  page.tsx                الصفحة الرئيسية
  (public)/
    directory/page.tsx    الصفحة العامة لدليل الكفاءات (تقرأ من View directory_public)
    join/page.tsx         نموذج طلب الانضمام (هيكل الخطوة الأولى)
    login/page.tsx        تسجيل الدخول برقم الهوية
  admin/
    layout.tsx            حماية /admin + التحقق من الدور (reviewer/admin)
    page.tsx               لوحة مؤشرات مبسطة
lib/supabase/
  client.ts               عميل Supabase لمكونات المتصفح
  server.ts               عميل Supabase لمكونات الخادم
proxy.ts                  تحديث الجلسة + إعادة توجيه /admin لغير المسجلين (اصطلاح Next.js 16 بديل middleware)
database/
  001_schema.sql           الجداول والعلاقات
  002_rls_policies.sql      سياسات الأمان (RLS)
  003_public_directory_view.sql   View العرض العام الآمن
  004_seed_reference_data.sql     بيانات مرجعية أولية
  README.md                 تفاصيل قرارات التصميم وطريقة التنفيذ
public/logo.png            الشعار الرسمي لمجلس عائلة النتشة
```

## خطوات التشغيل

### 1. المتطلبات

- **Node.js 20+** و npm — غير مثبّتين حاليًا على هذا الجهاز، يجب تثبيتهما أولًا من
  [nodejs.org](https://nodejs.org).
- حساب [Supabase](https://supabase.com) (مجاني للبدء).

### 2. تثبيت الحزم

```bash
npm install
```

### 3. إعداد Supabase

1. أنشئ مشروعًا جديدًا في Supabase (يُفضّل أن يكون تحت حساب مؤسسي للمجلس وليس حسابًا شخصيًا — القسم 62).
2. نفّذ ملفات `database/*.sql` بالترتيب المذكور في `database/README.md`.
3. انسخ `.env.example` باسم `.env.local` واملأ القيم من **Project Settings → API**.
4. **مهم:** من **Authentication → Sign In / Providers → Email**، عطّل **Confirm email**. النظام يُنشئ لكل مستخدم بريدًا داخليًا مصطنعًا (القسم 14) لا يستقبل رسائل فعلية، فبقاء هذا الخيار مفعّلاً يمنع أي حساب جديد من الحصول على جلسة دخول بعد التسجيل. الحماية الفعلية للنظام لا تعتمد على تأكيد البريد أصلاً، بل على المراجعة اليدوية قبل النشر (القسم 20-21).

### 4. تشغيل بيئة التطوير

```bash
npm run dev
```

يفتح الموقع على `http://localhost:3000`.

### 5. النشر

- **الكود:** يُرفع إلى مستودع **GitHub خاص** مملوك للمجلس (القسم 45).
- **الاستضافة:** ربط المستودع بـ **Vercel** ونسخ متغيرات البيئة نفسها هناك (القسم 46).

## حالة التنفيذ الحالية (نقطة انطلاق، وليست نسخة جاهزة للإنتاج)

هذا الهيكل يغطي دورة العمل الكاملة فعليًا على قاعدة بيانات حقيقية: تسجيل دخول
برقم الهوية، نموذج "طلب انضمام" (4 خطوات) يكتب في كل الجداول المعنية، شاشة
مراجعة واعتماد ونشر في لوحة الإدارة (القسم 21)، الدليل العام يعرض المعتمد
والمنشور فقط، و**"ملفي الشخصي"** (القسم 33) حيث يستطيع صاحب الحساب رؤية حالته
وتعديل بياناته — تعديلات بسيطة تُطبَّق فورًا، وتعديلات جوهرية (الاسم، التخصص،
المؤهل، جهة العمل، الترخيص) على ملف منشور مسبقًا تُرسَل كـ `change_requests`
بانتظار مراجعة الإدارة (القسم 34). كما تتوفر شاشات لإدارة البيانات المرجعية
(المجالات الصحية والتخصصات الرئيسية/الدقيقة، الفروع العائلية، الدول والمدن)
من لوحة الإدارة مباشرة دون الحاجة لكتابة SQL (القسم 7، 53، 54) — إضافة وتفعيل/
تعطيل فقط دون حذف، حفاظًا على السجلات المرتبطة. كما تعمل آلية **"نسيت كلمة
المرور"** الكاملة (القسم 36): طلب برقم الهوية والهاتف يُطابَق تلقائيًا مع
البيانات المسجلة، ثم شاشة في لوحة الإدارة يتحقق فيها المدير هاتفيًا من الشخص
قبل توليد كلمة مرور مؤقتة وتفعيلها فورًا (عبر دالة قاعدة بيانات محمية بدل
الاعتماد على بريد إلكتروني حقيقي غير متوفر أصلاً). وأصبحت شاشة **"طلبات
التعديل"** في لوحة الإدارة تعرض كل تعديل جوهري بانتظار المراجعة (قبل/بعد)
مع اعتماد يطبّقه فعليًا على الملف المنشور أو رفضه.

الشعار الرسمي (`public/logo.png`) يظهر الآن في هيدر وفوتر كل الصفحات العامة
(عبر `components/SiteHeader.tsx` و`SiteFooter.tsx` المطبَّقين تلقائيًا على
مجموعة `app/(public)`)، وكذلك في هيدر لوحة الإدارة و"ملفي الشخصي" — تطبيقًا
كاملاً للقسم 49.1.

شاشة مراجعة الطلب تعرض أيضًا **تنبيه تشابه محتمل** (القسم 22): تطابق تام في
الهاتف/الواتساب، أو تشابه في الاسم عبر `pg_trgm` (`similarity() >= 0.35`)، مع
أي مسجل آخر — تنبيه فقط للمراجع، بلا أي دمج أو حذف تلقائي.

**رفع الصورة الشخصية** (القسم 15) يعمل فعليًا الآن عبر Supabase Storage
(دلو `profile-photos`، حد 5 ميغابايت، JPG/PNG فقط) — من نموذج طلب الانضمام
(الخطوة 2) ومن "ملفي الشخصي" لاحقًا، مع عرضها للمراجع في شاشة اعتماد الطلب
ليتحقق من ملاءمتها قبل النشر.

شاشة **"التقارير"** الجديدة في لوحة الإدارة (القسم 30) تعرض بطاقات عددية
(الإجمالي/بانتظار المراجعة/معتمد/منشور/مرفوض دائمًا على كل السجلات)، وجداول
تفصيلية قابلة للتصفية بنطاق (كل السجلات / المعتمد فقط / المنشور فقط، القسم 56):
التوزيع حسب المجال الصحي، الدولة (مع فصل داخل/خارج فلسطين)، المؤهل العلمي،
وسنوات الخبرة. **التصدير** (القسم 32) متاح بصيغتين: **CSV** (يفتح مباشرة في
Excel، ويشمل رقم الهوية لأنه تصدير إداري مقصور على admin فقط)، و**PDF** عبر
صفحة قابلة للطباعة (`/admin/reports/print`) يحفظها المتصفح كـ PDF مباشرة —
دون الحاجة لمكتبة توليد PDF منفصلة.

> **قرار متعمّد:** لم تُستخدم مكتبة `xlsx` (SheetJS) لتوليد ملفات `.xlsx` حقيقية
> لأن نسخة npm الحالية تحمل ثغرتين معروفتين بلا إصلاح متاح. بما أن CSV يُفتح في
> Excel مباشرة بنفس النتيجة العملية، اعتُمد كبديل أكثر أمانًا. يمكن إعادة النظر
> لاحقًا إذا توفّر إصلاح أو ظهرت حاجة فعلية لتنسيق `.xlsx` أصلي (تنسيق خلايا،
> عدة أوراق، إلخ).

صفحة **الدليل العام** أصبحت أكثر ديناميكية بعد مراجعة مواقع مشابهة: شريط
إحصاءات بأعداد متحركة (`components/AnimatedNumber.tsx`) يعكس العدد الحقيقي
دائمًا (وليس أرقامًا ثابتة)، وسوم تخصصات سريعة أعلى النتائج (أكثر 6 تخصصات
انتشارًا فعليًا، بالضغط عليها تُصفّي القائمة فورًا)، وشارة **"انضم حديثًا"**
تلقائية على أي ملف اعتُمد خلال آخر 30 يومًا — كل ذلك محسوب من البيانات
الفعلية دون أي إدخال يدوي.

**صفحة "الكفاءات الصحية بالأرقام" العامة** (`/stats`، القسم 31) تعرض إحصاءات
مجمّعة فقط (بلا بيانات شخصية): التوزيع حسب التخصص والدولة، وداخل/خارج فلسطين
— مصممة لتكون قابلة للمشاركة والفخر العائلي. كما أضيفت **أزرار مشاركة عبر
واتساب** (`components/WhatsAppShareButton.tsx`) في الصفحة الرئيسية وكل ملف
شخصي عام، تفعيلاً لأقصر مسافة بين مشاهدة الدليل ودعوة أحد أفراد العائلة له.

**طلب حذف الحساب نهائيًا** (القسم 38) يعمل الآن أيضًا: من "ملفي الشخصي" يمكن
لصاحب الحساب طلب الحذف بعد تأكيد صريح، فيُخفى ملفه فورًا (حالة "موقوف")، ثم
تصل الإدارة إلى شاشة **"طلبات الحذف"** حيث يمكنها إما **الحذف النهائي** (يمسح
فعليًا بيانات الهوية/الاتصال/الملف/البيانات المهنية، ويقفل تسجيل الدخول
نهائيًا) أو **الرفض واستعادة الحساب** لحالته السابقة — احترازًا من طلب حذف
كيدي من حساب مخترق.

> **ملاحظتان صادقتان حول هذا التنفيذ:**
> 1. الوثيقة تذكر مهلة "خلال 30 يومًا" قبل الحذف الفعلي؛ نُفِّذ هنا **حذفًا
>    فوريًا عند تأكيد المدير يدويًا** بدل جدولة تلقائية (لا توجد بعد وظيفة
>    مجدولة/Cron في المشروع)، وهذا يفي بالغرض العملي لكنه ليس مطابقًا حرفيًا
>    لرقم المهلة.
> 2. لا يُحذف حساب Supabase Auth فعليًا (يتطلب Service Role Key الذي لم
>    نستخدمه عمدًا في هذا المشروع)؛ بدلاً من ذلك يُقفل الدخول نهائيًا بكلمة
>    مرور عشوائية طويلة لا يعرفها أحد — النتيجة العملية واحدة (لا يمكن الدخول
>    مطلقًا)، لكنه ليس حذفًا فعليًا لسجل المصادقة نفسه.

بهذا اكتملت كل عناصر قائمة الإصدار الأول (القسم 59) المذكورة أصلاً في هذا
الملف.

### تحسينات على الدليل العام (بعد مراجعة مواقع مشابهة كـ altibbi.com)

- **صفحة ملف عام فعلية** لكل شخص (`/directory/[id]`) لم تكن موجودة سابقًا —
  تعرض Breadcrumb كامل، بيانات الاتصال المسموح بها، ونبذة مهنية.
- **إخفاء الهاتف/الواتساب خلف زر "اضغط لإظهار الرقم"** (`components/RevealField.tsx`)
  بدل عرضهما كنص مباشر قابل للحصاد الآلي من محركات البحث أو الروبوتات.
- **أيقونة افتراضية أنيقة** (`components/DirectoryAvatar.tsx`) بدل مربع فارغ
  عند غياب الصورة الشخصية.
- **شارة توثيق** ملاصقة للاسم (`components/VerifiedBadge.tsx`) في البطاقة
  وصفحة الملف.
- **قسم "كفاءات أخرى في نفس التخصص"** أسفل كل ملف شخصي، لتشجيع تصفح إضافي.

## تذييل الصفحات وسياسة الخصوصية

**التذييل** (`components/SiteFooter.tsx`) أصبح أكثر اكتمالاً: روابط سريعة
لأهم صفحات الموقع، شعار المجلس بحجم مصغّر مناسب لعنصر تذييل، وأيقونة **فيسبوك**
تربط مباشرة بصفحة المجلس الرسمية (facebook.com/natshehcouncil). تحته اسم
الجهة المشرفة "المجلس العائلي لعائلة النتشة — فلسطين، الخليل"، سطر حقوق نشر
بالسنة الحالية محسوبة تلقائيًا، وسطر اعتماد "تصميم وإعداد: د. أحمد عوني
النتشة". لا يوجد بعد رقم هاتف أو بريد إلكتروني رسمي للتذييل — سيُضافان عند
توفرهما.

**صفحة سياسة الخصوصية والاستخدام** (`/privacy`) جديدة بالكامل، وتشرح بلغة
واضحة غير قانونية جامدة: من يشرف على الدليل، أنواع البيانات المجمّعة والغرض
منها، الفرق بين ما ينشر للعامة وما يبقى داخليًا فقط (القسم 36)، آلية المراجعة
قبل النشر، من يملك صلاحية الوصول للبيانات الكاملة، حق التعديل والحذف النهائي
للحساب، مدة الاحتفاظ بالبيانات، وسياسة عدم فهرسة الملفات الشخصية في محركات
البحث. رابطها مضاف في تذييل كل صفحة عامة، وكذلك كخانة إلزامية للموافقة عليها
ضمن نموذج طلب الانضمام (`app/(public)/join/page.tsx`).
